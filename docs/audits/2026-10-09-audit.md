**Top items requiring attention this cycle**:
1. H-1 — no branch protection on `main` or `stage`, and a push to `stage` deploys production.
2. H-2 — Cognito MFA is off; a phished password is enough to mint a write API key, which is now usable over the internet.
3. H-4 — the model bucket is not versioned in code, while agents can now rewrite models over MCP.
4. H-3 — the site sends no security headers.

Nothing found is an active exposure. The new internet-facing pieces (two Function URLs) hold up: no key or a wrong key gets 401, browsers on other origins are refused, no key material reaches the logs, and a read key cannot write (checked live).

## Findings

### HIGH

#### H-1. No branch protection, and `stage` deploys production
**Domain**: CI
**Evidence**: `gh api repos/d-lab-5/blueprinting-dlab5-net/branches/{main,stage}/protection` → `404 Branch not protected`. `aws amplify get-branch … stage` → `stage: PRODUCTION, enableAutoBuild: true`; `main` is not connected to the app. Both `blueprinting.dlab5.net` and `stage-blueprinting.dlab5.net` are served from `stage`.
**Impact**: In a public repository, anyone with push access — or a leaked GitHub token — can push to `stage` and it ships to production, backend included (`ampx pipeline-deploy`), with no review and no status check. Force-pushes can rewrite history.
**Remediation**: Protect `stage` and `main`: no force-push, no deletion, required status check (the Amplify build or a GitHub Action running `npm test` + `npm run build`). Decide whether production should track `main` via promotion PRs (as CLAUDE.md already describes) rather than `stage`.

#### H-2. Cognito MFA off; password minimum 8
**Domain**: Auth
**Evidence**: `aws cognito-idp describe-user-pool` → `MfaConfiguration: OFF`, `MinimumLength: 8` (complexity rules on).
**Impact**: One password is the only factor, and since ADR-0012/0014 a signed-in session can mint a **write** API key that works from anywhere through the hosted MCP endpoint and is not tied to a browser. A phished or reused password therefore becomes a durable write credential for every product its owner belongs to, until someone notices and revokes the key. Admin accounts (bp-admins) are the sharpest case, although key sessions strip bp-admins.
**Remediation**: Enable TOTP MFA, at least as "optional" with enforcement for bp-admins; raise the minimum length to 12+. Consider requiring a fresh sign-in (or MFA) to create a write key.

#### H-3. No security headers on the site
**Domain**: Frontend
**Evidence**: `curl -sI https://blueprinting.dlab5.net/` returns none of `Strict-Transport-Security`, `Content-Security-Policy`, `X-Content-Type-Options`, `X-Frame-Options`/`frame-ancestors`, `Referrer-Policy`, `Permissions-Policy`. No `customHttp.yml`, no `customHeaders` on the Amplify app.
**Impact**: The app renders user- and now agent-supplied Markdown and SVG (`renderMarkdown`, Mermaid, D2). Those paths are defended (see "checked clean"), but there is no second line if one of them regresses; the app can also be framed (clickjacking on approve/delete actions).
**Remediation**: Add `customHttp.yml` (or Amplify custom headers) with HSTS, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `frame-ancestors 'none'`, a `Permissions-Policy`, and a CSP starting from `default-src 'self'` plus the Cognito, AppSync and S3 origins (D2's WASM worker and Mermaid will need `'wasm-unsafe-eval'` / worker-src; test before enforcing, ideally Report-Only first).

#### H-4. Model store not versioned, now that agents write models
**Domain**: Data
**Evidence**: `backend/amplify/storage/resource.ts` and `backend.ts` declare no versioning for the model bucket (the only PITR is on the Project and View tables, `backend.ts:68-72`). Live check not possible: `dlab5_devops` lacks `s3:GetBucketVersioning` on that bucket.
**Impact**: The ABox in S3 is the source of truth (ADR-0003). The ETag precondition prevents a lost update, not a bad one: a write key used by an agent — possibly steered by text it read (see I-3) — can remove elements in sequence, and each write is a valid overwrite. Without versioning there is no way back. The project-docs bucket, by contrast, is versioned and has no delete.
**Remediation**: Enable versioning on the model bucket with a noncurrent-version expiry (e.g. 90 days), via CDK on the storage resource. Verify live afterwards. Consider the same for the Document table (L-2).

### MEDIUM

#### M-1. Build-chain dependency advisories (Gatsby tree)
**Domain**: Deps
**Evidence**: `npm audit --omit=dev` (root): 2 critical, 56 high, 29 moderate, 9 low. Criticals: `shell-quote` (command injection in `quote()`), `proxy-addr` (IP spoofing). Highs are almost all Gatsby, graphql-codegen, webpack, eslint, sharp. `backend/`: 0.
**Impact**: These run at build and dev time; the site is static output, so the runtime exposure is small. Build-time packages still run with the Amplify build role's credentials.
**Remediation**: `npm audit fix` for non-breaking bumps; track Gatsby 5 patch releases; re-audit after. Not urgent per package, worth a pass per quarter.

#### M-2. Dependabot disabled
**Domain**: CI
**Evidence**: `gh api …/dependabot/alerts` → "Dependabot alerts are disabled for this repository"; `dependabot_security_updates: disabled`.
**Remediation**: Enable Dependabot alerts (and optionally security updates with a weekly schedule) so M-1-type issues surface without an audit.

#### M-3. Deploy user: broad rights on a long-lived key
**Domain**: CI / IAM
**Evidence**: IAM console (screenshot 2026-10-09): `dlab5_devops` has `AdministratorAccess-Amplify` and `AmplifyBackendDeployFullAccess` through group `DLAB5_Devops`, plus the two scoped deploy policies; access key 1 is 172 days old and used daily from this workstation.
**Impact**: `AdministratorAccess-Amplify` can create IAM roles and much else; a leak of that key from the workstation is a broad compromise.
**Remediation**: Rotate the key now and on a 90-day cycle; prefer short-lived credentials (IAM Identity Center / `aws sso login`) for the workstation. Keep the two scoped deploy policies — they are the right shape.

#### M-4. project-docs: one key reaches every product's space
**Domain**: Auth / Data
**Evidence**: ADR-0013; `mcp/project-docs/src/auth.py` (single SSM key), `template.yaml` (no `ReservedConcurrentExecutions`). `aws lambda get-function-concurrency` → none.
**Impact**: Anyone holding the project-docs key can read and write the shared files of every product, regardless of their blueprinting groups; and unauthenticated traffic is unbounded (each 401 is still a Lambda invocation — a cost exposure, not a data one). Accepted in ADR-0013 for phase 1, recorded here so it is not forgotten.
**Remediation**: Add reserved concurrency (e.g. 5) to the project-docs function. For access, either accept as-is while only one person holds the key, or move project-docs onto the same per-user identity as the hosted blueprint MCP (blueprinting API keys + product groups).

#### M-5. Deployed code not in git
**Domain**: Quality / CI
**Evidence**: `git status` — 27 changed files uncommitted, including `packages/mcp/src/{appsync,data,http,session,server}.ts` and `packages/mcp/hosted/`, which are **deployed** as the `blueprint-mcp` stack.
**Impact**: What runs in AWS cannot be reproduced or reviewed from the repository; a workstation loss would lose the source of a live endpoint.
**Remediation**: Commit (after review) before the next deploy; make "deploy from a clean, pushed tree" the rule in `dlab5-git-push`.

#### M-6. Cognito deletion protection off
**Domain**: Auth
**Evidence**: `describe-user-pool` → `DeletionProtection: INACTIVE`.
**Impact**: A mistaken stack operation or a broad IAM key can delete the user pool and every account with it.
**Remediation**: Set `deletionProtection: ACTIVE` on the pool (CDK override in `backend.ts`).

### LOW

#### L-1. MCP SDK 1.30.0 and fast-uri advisories in the Lambda bundles
**Domain**: Deps
**Evidence**: GHSA-6qxp-vccf-f47h (`@modelcontextprotocol/sdk` 1.12.0–1.30.1: the **OAuth client** may send credentials to an authorization server chosen by the server); three `fast-uri` advisories via ajv.
**Impact**: Not exploitable here: both servers are MCP servers and never run the SDK's OAuth client; ajv resolves only our own schema URIs. Hygiene only.
**Remediation**: Bump the SDK to ≥ 1.30.2 and rebuild the hosted bundle.

#### L-2. Document table without point-in-time recovery
**Domain**: Data
**Evidence**: `backend.ts:68` enables PITR for `Project` and `View` only.
**Remediation**: Add `"Document"` to that list.

#### L-3. A revoked key keeps working for up to an hour
**Domain**: Auth
**Evidence**: `packages/mcp/src/session.ts` caches the access token per key until 5 min before expiry; Cognito tokens live 60 min (`backend.ts:415-417`).
**Impact**: Revocation stops new exchanges immediately, but a token already issued — in the hosted cache or held by a stdio client — remains valid until it expires. Same as any Cognito session.
**Remediation**: Document it in ADR-0012/0014 ("revocation takes effect within an hour"). Cognito has no per-key revoke for tokens already issued, so the lever is a shorter token lifetime on the two key clients (e.g. 15 min).

#### L-4. project-docs does not refuse credential-shaped content
**Domain**: Data
**Evidence**: `mcp/project-docs/src/rules.py` checks path, type and size only. The product document store refuses tokens (`documentStore` `SECRET_SHAPES`), and Publish goes through that check — but shared files themselves are shown to the whole product group on the Documents page.
**Remediation**: Apply the same `SECRET_SHAPES` refusal in `write_doc`.

#### L-5. Deploy policies allow CreateChangeSet on any stack name
**Domain**: IAM
**Evidence**: `deploy-policy.json` (both) `StackTooling` grants `cloudformation:CreateChangeSet` on `*`. During this work it created an empty `blueprint-mcp` stack in `REVIEW_IN_PROGRESS` under the wrong policy.
**Remediation**: Scope `CreateChangeSet` to the stack ARNs and to the SAM transform ARN.

#### L-6. Docs drift: dangling ADR-0006, SECURITY.md silent on the new endpoints
**Domain**: Docs
**Evidence**: ADR-0006 is cited in code and CLAUDE.md but `docs/adr/0006-*.md` does not exist. `SECURITY.md` design invariants predate the two public Function URLs.
**Remediation**: Write or re-number ADR-0006 (the CloudFormation-cycle decision); add an invariant to SECURITY.md: "Public endpoints authenticate every request in the app (bearer key / API key), log no key material, and are rate-limited by reserved concurrency."

### INFO

#### I-1. Production is the `stage` branch
`main` is not connected to Amplify; merging a promotion PR deploys nothing. Worth stating in CLAUDE.md, which says "`main` is only updated by a promotion PR" as if it deployed.

#### I-2. Reserved concurrency trades availability for cost
The hosted MCP caps at 5 concurrent requests. A flood of keyless requests is rejected cheaply but can still crowd out real ones for its duration. Acceptable for one user; revisit if claude.ai use grows.

#### I-3. Agents read content that others wrote
Models, documents and shared files reach claude.ai and Claude Code verbatim. Text in them can try to steer an agent that holds a write key. Mitigations already in place: read keys by default, agents propose and people import for documents (ADR-0011). H-4 is the missing undo.

#### I-4. claude.ai request-header connectors are organisation-wide on Team/Enterprise
On those plans a connector added by an Owner shares its header value with every member. On a personal plan it is personal. Use a read key, or a dedicated user's key, for any shared connector.
